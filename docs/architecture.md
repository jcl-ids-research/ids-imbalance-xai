# RM-DMVT 工程架构

面向开发者的模块边界说明。面向使用者的入口请看 [项目手册](项目手册.md)。

## 数据流

```text
官方训练集（四个基准之一）
  ├─ 训练集内划分验证集
  ├─ 分位变换 + 类别条件 DDPM（仅训练集拟合）
  ├─ 逆分位数变换
  ├─ 离散边缘秩匹配校正
  └─ 受扩增上限约束的平衡训练缓存
           ↓
  多视图 Transformer 分类器（同时产出四个消融变体）
           ↓
  未经修改的真实测试集（仅最终评估一次）
           ↓
  与服务器归档结果逐指标比对
```

## 模块边界

| 目录 | 责任 |
|---|---|
| `config.py` `types.py` `errors.py` `utils.py` | 不可变配置、领域类型、类型化错误、随机种子与日志 |
| `data/` | 四数据集加载、官方划分、训练侧预处理、视图映射、缓存、保留集 |
| `models/` | DDPM、多视图/单视图编码器、分类头 |
| `training/` | 生成、校正、重平衡、训练、指标、四变体 pipeline |
| `tuning/` | Optuna 搜索空间与验证集目标函数 |
| `reproduction/` | 论文运行矩阵、可续跑执行器、归档比对、论文数字重算 |
| `cli/` | 9 个真实运行入口，供终端与 PyCharm 共用 |

## `data/` 的分工

| 模块 | 责任 |
|---|---|
| `registry.py` | 按数据集名分派加载器与视图划分，是唯一对外入口 |
| `unsw.py` `nslkdd.py` | 官方划分基准，支持二元与多类 |
| `cic.py` | 无官方划分，按种子分层切分并限定读取规模 |
| `tabular.py` | 共享的训练侧编码、缺失值填充、零方差剔除与标准化 |
| `views.py` | 语义视图与位置视图划分 |
| `splits.py` `cache.py` `holdout.py` | 验证集划分、缓存读写、外层保留集 |

新增数据集只需实现加载器并在 `registry.py` 注册，CLI、调优与复现驱动无需改动。

## `reproduction/` 的分工

| 模块 | 责任 |
|---|---|
| `jobs.py` | 定义论文的 18 次运行（四基准二元 + 两基准多类 × 三种子） |
| `runner.py` | 预检、执行、写缓存与指标、已完成任务自动跳过 |
| `evidence.py` | 读取服务器归档结果并与新跑结果逐指标做差 |
| `claims.py` | 直接从归档重算论文头条数字，无需 GPU |
| `measurements.py` | 从归档读出可比数值，不感知论文怎么写 |
| `fidelity.py` | 校正代价与 MMD² 改善的专有计算 |
| `archive_io.py` | 在边界处把归档 JSON 收窄成类型化对象 |
| `families.py` | 全部论文实验族清单，区分 maintained 与 archived-only |

## 防泄漏的结构性设计

- 调优使用的缓存类型 `PreparedInner` **在类型上就不含评估分区**，搜索代码无处可读测试数据；
- 把带评估矩阵的缓存传给调优加载器会立即抛错，而不是静默通过；
- 所有预处理统计量只在训练分区拟合，测试分区仅被变换。

## 公平调优约束

1. 测试集不参与 trial 选择；
2. 分类器调优阶段固定合成样本；
3. 四消融变体使用配对初始化；
4. 候选参数先单种子筛选，最终前三名再用 42/123/456 复核；
5. 最终配置在四个数据集上统一复跑。
